# Plannova 项目规划书

> 版本：v0.1 ｜ 状态：草稿 ｜ 最后更新：2026-11-26
>
> 这份文档的用途不是"交作业"，而是**你自己写代码时回来查的东西**。
> 每一条如果写不出可验证的标准，就说明还没想清楚。

---

## 1. 项目概览

| 项 | 内容 |
| --- | --- |
| 项目名称 | Plannova |
| 一句话定位 | 把「项目开始前的想法」变成「结构化规划文档」的 Web 工具 |
| 类型 | □课内练习　□简历项目　☑个人作品 / Demo |
| 目标用户 | 主要是自己；其次是同样需要理清开题思路的学生开发者 |
| 完成标准 | 能完整走通一次：新建项目 → 逐节填写 → 导出规划文档 |
| 不做成什么样 | 不做通用笔记软件、不做团队协作、不做后端账号体系 |

**为什么要写"不做成什么样"**：项目烂尾最常见的原因不是做不出来，而是边界一直在扩。
先把"这不是什么"钉死，比写"这是什么"更有约束力。

## 2. 需求边界

行业里叫 **MoSCoW 方法**：Must / Should / Could / Won't。你原模板用了 P0/P1，本质一样，
但加一条「验收标准」会让它真正可用——**写完一条需求，必须能回答"怎么算做完了"**。

### P0 — 必做（砍掉就不成立）

| # | 需求 | 验收标准（怎么算做完） |
| --- | --- | --- |
| 1 | 单个规划项目的新建 / 重命名 / 删除 | 刷新后数据仍在；删除有二次确认 |
| 2 | 按固定章节结构填写内容 | 每节可独立编辑，切换节不丢失已填内容 |
| 3 | 实时预览最终文档 | 编辑区改动后预览同步更新，无需手动刷新 |
| 4 | 导出为 Markdown 文件 | 导出的 .md 能在 Typora / VSCode 正常渲染，层级正确 |
| 5 | 本地持久化 | 关闭浏览器重开后内容完整恢复 |

> 💡 **学习点**：验收标准要写成"可观测的行为"，不能写"功能完善""体验良好"。
> 面试时聊需求，这条能立刻显出差别。

### P1 — 加分（有余力再做）

| # | 需求 | 验收标准 |
| --- | --- | --- |
| 1 | 章节完成度进度条 | 填过内容的章节计入，空章节不计入，百分比正确 |
| 2 | 内置模板切换（Web / 课设 / 比赛） | 切换后章节结构变化，同名章节内容保留 |
| 3 | 导出为 PDF | 版式不错乱，中文正常显示 |
| 4 | 深浅色主题切换 | 偏好被记住，刷新不重置 |

### 明确不做（Won't）

1. 用户注册登录 / 多端同步 —— 无后端，纯前端
2. 多人协作、评论、分享链接
3. 富文本编辑器（只做 Markdown 或纯文本）
4. 移动端深度适配（只保证能看，不做手势交互）

## 3. 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | HTML + CSS + 原生 JS（ES Module） | 不引框架，重点练 DOM 与状态管理 |
| 构建 | 无构建 | 直接打开 index.html 可跑，降低上手成本 |
| 存储 | localStorage | 无后端；单机够用 |
| 样式 | 原生 CSS + CSS 变量 | 变量是主题切换和响应式的基础 |
| 第三方库 | 仅按需：Markdown 渲染库（如 marked） | 其余自己写 |

> 💡 **学习点**：技术选型的价值在于**写下"为什么不选另一个"**。
> 只写"我用 localStorage"没意义，补上"不选 IndexedDB，因为数据量小、不需要异步"
> 才是决策记录（ADR 的思路）。

## 4. 数据模型与结构设计

这是 JS 部分的蓝图，界面按它来定钩子。

### 4.1 核心数据结构（草案）

```js
// 一个规划项目
{
  id: "uuid",
  title: "项目名",
  template: "web",          // web | course | contest
  createdAt: 1732...,
  updatedAt: 1732...,
  sections: [
    {
      key: "overview",
      title: "项目概览",
      type: "kv",           // kv 键值对 | table 表格 | text 长文本 | list 列表
      content: { ... },     // 结构由 type 决定
      completed: true
    }
  ]
}
```

### 4.2 目录结构

```
Plannova/
├── index.html          入口
├── css/
│   ├── tokens.css      设计变量（颜色/间距/字号）—— 换肤只改这一个文件
│   ├── base.css        重置与基础排版
│   └── layout.css      页面骨架与组件样式
├── js/
│   ├── main.js         入口：初始化、事件绑定
│   ├── store.js        状态容器与 localStorage 读写
│   ├── render.js       DOM 渲染
│   └── export.js       Markdown / PDF 导出
└── resources/
    └── plan.md         本文件（同时可作内置模板来源）
```

> 💡 **学习点**：`store.js` / `render.js` 的分离就是**单向数据流**的最小实践——
> 改数据 → 重新渲染，而不是到处 `querySelector().innerHTML = ...`。
> 这是从"写能跑的代码"到"写能改的代码"的关键一步，简历里值得写。

### 4.3 数据流向

```
用户输入 → 事件处理 → store 更新 → 触发 render → 视图更新
                ↓
         写入 localStorage（防抖）
```

## 5. 难点与风险

| 难点 | 应对方案 | 备选方案 |
| --- | --- | --- |
| 各章节结构差异大（表格 / 文本 / 列表），渲染会分叉 | 用 `type` 字段驱动，每种 type 一个渲染函数，注册到 map | 统一退化成纯文本，牺牲结构换速度 |
| 实时预览性能（每次按键都重渲染） | 输入做 300ms 防抖 | 改成点"预览"按钮才刷新 |
| 导出 Markdown 时表格/列表格式易错 | 先写死 2～3 个章节验证格式，再扩展 | 先导出纯文本，放弃格式 |
| 状态与 DOM 不同步、越写越乱 | 严格走"改 store → 重渲染"，不直接操作 DOM 内容 | 停在 P0，不做实时预览 |

## 6. 迭代计划

按**能跑的最小闭环**排，不是按功能模块排。

| 阶段 | 目标 | 完成标志 |
| --- | --- | --- |
| M1 骨架 | 页面结构 + 静态样式成型 | 打开页面能看到完整布局，无 JS 也能看 |
| M2 数据层 | store 读写 + localStorage 持久化 | 控制台能增删改一个项目并持久化 |
| M3 单章节闭环 | 一个章节可编辑、可保存、可渲染预览 | 填内容 → 刷新 → 内容还在 |
| M4 全章节 | P0 的 5 条需求全部走通 | 能从头到尾做出一个完整项目 |
| M5 导出 | Markdown 导出可用 | 导出的文件能在编辑器正常渲染 |
| M6 P1 | 按剩余时间挑 1～2 条 | 自己用着觉得顺 |

**止损线**：M4 完成前不碰任何 P1 功能。
时间不够就**砍掉 P1 全部，保住 M1～M4 完整能跑**——能跑完的 60%，比跑不完的 100% 值钱。

## 7. 工程准备

- **Git**：初始化仓库，首次提交就把本文件提交上去
- **.gitignore**：至少忽略 `.DS_Store`、`node_modules/`、`*.log`
- **提交规范**：`feat: 新增章节编辑` / `fix: 修复刷新丢数据`（Angular 风格前缀，够用且通用）
- **分支**：单人项目直接 main，别为了"规范"搞分支浪费精力
- **资源目录**：`resources/` 放模板与文档，图片暂不需要可先不建

> 💡 **学习点**：提交信息写清楚，半年后看 `git log` 能读懂自己当时在干什么。
> 这比任何"代码规范文档"都实在。

## 8. 测试清单

按"写完一块验一块"，不要最后统一测。

**正常场景**
- 新建项目 → 填入全部章节 → 刷新 → 内容完整
- 导出 Markdown → 用 Typora 打开 → 标题层级、表格、列表均正确

**边界场景**
- 标题留空、章节全空时导出的文件长什么样
- 超长文本（粘贴 5000 字）输入是否卡顿
- 标题含特殊字符（`#`、`|`、换行）时导出是否破格式
- 多次新建删除后 localStorage 是否残留脏数据

**异常场景**
- localStorage 被手动清空 → 页面优雅降级而非白屏
- localStorage 容量超限 → 有提示而非静默失败
- 浏览器禁用 JS 时至少有提示
